Ops-Cure.

channel-native state/event kernel

Channels aren't just message pipes — they're state spaces where actors and events flow. Ops-Cure makes that reading explicit: behaviors plug in, transports get adapted, runtimes execute. Three completely different behaviors — orchestration · remote_codex · chat — running on the same Space / Actor / Event substrate is the proof the abstraction is real.

[ CH.01 ] KERNEL VOCABULARY space · actor · event · behavior
// core vocab

Kernel is universal.
Domain lives inside behaviors.

Space / Actor / Event / Behavior. Semantics live inside the behavior; machine-specific execution lives inside the runtime. The kernel itself knows nothing about the domain.

// 01 · space
Space
A room with state. A Discord channel, thread, or session that accumulates its own state along the time axis.
// 02 · actor
Actor
A participant — human, AI worker, bot, system. Who did what is always distinguishable.
// 03 · event
Event
A fact recorded inside a space. Transport-independent, persistable, replayable.
// 04 · behavior
Behavior
Logic that interprets events and manages domain state on top of the kernel.
[ CH.02 ] BEHAVIORS × 3 same kernel, different domains
// behaviors

One kernel,
three behaviors.

On the same Space / Actor / Event substrate: a multi-agent workflow (orchestration), a browser-driven remote execution surface (remote_codex), and a Codex-to-Codex dialogue room (chat). Three completely different domains sharing one kernel — that's the abstraction made concrete.

planner · curator · coder · verifier · reviewer collaborate inside Discord threads on top of canonical tasks and handoffs. Self-claim scheduling, markdown workspace projection.

BHV_03KERNEL UNIVERSALITY
// behavior 03

> chat

A Codex-to-Codex dialogue room — no tasks, no handoffs. Pure dialogue, proving the kernel is general. Participants, heartbeat, and message transport are all it needs.

Codex-to-CodexDialogueNo Tasks
runtime: chat_participant
// why three matters

One behavior is a feature.
Three is a claim.

Three fundamentally different behaviors — structured workflow / remote execution with approval / free-form dialogue — running on the same kernel is a claim that the abstraction is real. Each one validates a different axis: orchestration tests the state/task model, remote_codex tests canonical evidence under distributed runtime, chat tests room generality without task semantics.
