// ai dev tool · shipping

Don't open the laptop —
resume your local Claude Code sessions
right where you left off.

DeskRelay is a self-host developer tool that remotes Claude Code sessions running on your own PC to a browser or mobile, safely. A single server PC runs site-frontend, site-backend, and a local connector daemon. Other PCs in the same LAN or Tailscale tailnet register as devices.

[ CH.01 ] WHAT IT DOES 3 capabilities
// product · capabilities

Slots into the workspace
you use every day.

Not a demo controller — a tool designed to plug into a real daily workflow. Mobile, self-host, and multi-PC are treated as first-class concerns, not afterthoughts.

CAP_01MOBILE
// 01 · mobile

Same session on the move.

The Android Capacitor app and mobile browser pick up the same session you left on the desktop. Chat, sessions, permissions, instructions, and skills tabs are arranged for the mobile flow.

CAP_02SELF-HOST
// 02 · self-host

Your PC is the server.

No external server needed — your own desktop runs site-frontend(:18193), site-backend(:18192), and the connector daemon together. No tokens or keys handed off to a third party.

CAP_03MULTI-PC
// 03 · multi-pc

Many PCs, one screen.

Register Windows PCs in your Tailscale tailnet or LAN as devices and switch between them in a single browser UI. Each PC runs its own :18091 connector daemon.

[ CH.02 ] ARCHITECTURE 4 layers
// architecture

Designed as
a developer tool.

A flow that starts in the browser and ends inside the user's PC. The outside is the product shell; the inside is the user's PC runtime authority. The sensitive execution surface never leaks outward.

01
// site-frontend
Browser SPA · :18193

Single-page app built with Solid + Vite. The first surface the user sees.

↓
02
// site-backend
Hono + Bun · :18192

Self-host backend that bridges the browser and the connector-daemon URLs the user has registered. State registry in .self-server/state.

↓
03
// connector daemon
pc-connector-daemon · :18191 / :18091

Private HTTP API that exposes local Claude Code behavior. Runs on both the server PC and every registered PC.

↓
04
// behavior-remote-claude
Claude Code CLI

Spawns the local claude CLI on the user's PC and streams stream-json output as kernel events.

// engineering decisions
[t] transport
Private network first. Designed to operate only inside a LAN or a Tailscale tailnet.
[s] session
Site-token login. Device registration data lives in .self-server/state.
[r] registration
Paste the registration command from the main screen into the target PC's PowerShell — repo install, connector launch, address detection, validation, and device registration all run automatically.
[l] logging
Local connector validation report. Never sent off the machine.
[u] update
Self-host release channel — users update directly. Separate from the Play Store channel.
[ CH.03 ] DEVICE LIFECYCLE install → register → operate
// device lifecycle

Install & registration
are the product's spine.

The README walks through server install, access URL & token, registering other PCs, validation reports, updates, and troubleshooting in a single flow. Goal: end-to-end in under 30 minutes.

STEP_01INSTALL
// start on the server PC

One install script.

Run the install script from Windows PowerShell or macOS Terminal. After install, the default browser auto-opens to http://127.0.0.1:18193.

$ curl -L ... | sh
> opened http://127.0.0.1:18193
STEP_02REGISTER
// register another PC

One command, done.

Paste the registration command from the main screen into the target Windows PC's PowerShell. Repo install/update, connector launch, Tailscale/LAN address detection, server reachability check, and device registration happen in one shot.

> registering PC...
> connector :18091 OK
> device added_

Daily operation.

[ CH.04 ] TRUST BOUNDARY private-network first
// trust boundary

Private network first.
Local authority stays local.

The README states it plainly: do not expose connector ports directly to the public internet. If external access is needed, use a private network like Tailscale. Registering another PC also requires the same LAN or the same Tailscale tailnet.

Troubleshooting stays inside that boundary too. If a device doesn't appear in the list, check — in order — the server URL, same LAN/Tailscale, the target PC's 18091 port, firewall, registration report, then the connector validation report.

[ NOTES ] ENGINEERING DEPTH why dev-tool grade
// notes

Why push it
to tool-grade.

It started as a small remote controller. But once I was using it daily in my own workflow, the parts that make a tool feel like a tool — stability, recovery, auth, logging — quickly became the main story.

The Android app was built as a Capacitor wrapper while I worked out the permissions model, signing, and release channels. The self-host path was tightened so a non-developer can get it running in under 30 minutes.

The result isn't a portfolio demo — it's a developer tool I rely on every day. Having built and operated this kind of tool first-hand is the most direct evidence I can offer that I would carry the same posture into the next role.
