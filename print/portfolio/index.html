AI Systems · 1/2

Agent workflow kernel · self-host developer tool

Agent Workflow Kernel

Ops-Cure Kernel

orchestration, remote_codex, and chat store their state and events through the same Space / Actor / Event / Behavior model.

  • Problem: Orchestration, remote execution, and chat need different screens but share the same state and event storage model.
  • Build: Channel-native state/event core on FastAPI + SQLite. Discord transport, behavior plugin registry, canonical DB, three behaviors (orchestration / remote_codex / chat), three runtimes (pc_launcher · remote_executor · chat_participant).
  • Outcome: orchestration, remote_codex, and chat all store their state and events through the same Space/Actor/Event model.
Self-host Developer Tool

DeskRelay

A self-host developer tool that remotes Claude Code sessions running on your own PC to a browser or mobile. A single server PC runs site-frontend, site-backend, and a connector daemon. Other PCs in the same LAN or Tailscale register as devices.

  • Problem: Local agent tools are powerful because they sit beside the user's repos, shell, and tokens — but that also pins work to one keyboard.
  • Build: Solid + Vite SPA (:18193), Hono + Bun backend (:18192), pc-connector-daemon (:18191 / :18091), behavior-remote-claude, Capacitor Android app, registration automation + validation report.
  • Outcome: Public v0.0.0 self-host tool at github.com/darkhtk/deskrelay, used to manage my own sessions across multiple PCs.

AI Systems · 2/2

Local LLM R&D · mobile RAG product

Local LLM R&D

GenWorld + Ollama

Ported a Phaser 3 TS-based RPG to Unity 2D C# while designing a local Ollama LLM-backed NPC cognition / dialogue system. The game uses local LLM dialogue when available and a rule-based dialogue graph when the service is offline.

  • Problem: The game has to keep running when the optional LLM service stops responding.
  • Build: Stored NPC memory, mood, and skill state. A pre-defined dialogue graph handles response timeouts and offline mode.
  • Outcome: LLM dialogue runs while the service is available; the same NPC switches to the rule-based graph when it is not.
Mobile RAG Product

Oracluna Tarot

At oracluna.com, users choose a concern, shuffle and cut the deck, pick from a 78-card wheel, receive an interpretation, and save or share the result.

  • Problem: Mobile users needed to browse all 78 cards without losing the selected cards or their position in the deck.
  • Build: Draggable 78-card wheel, selection slots, spread and orientation data, Qdrant retrieval, Ollama/OpenAI provider adapters, browser storage, Canvas posters, and Web Share.
  • Outcome: Public service at oracluna.com with question entry, card selection, readings, saving, deletion, and sharing.

Industrial Software · 1/2

Robotics control · operator tooling

Industrial XR × Robotics

VR Robot Teleoperation

A full Quest 3 to Doosan A0912 control path through Unity, Flask, RoboDK, calibration, safety logic, and later in-house Jacobian IK ownership.

  • Problem: XR input had to control an industrial robot with stable mapping, safe movement, and operator-readable constraints.
  • Build: Controller filtering, coordinate transforms, bridge APIs, safety boxes, deadman logic, resend control, and IK continuation.
  • Outcome: Public demo at BEXCO with live Quest 3 input, robot movement limits, calibration, and operator safety controls.
Simulation Tooling · Digital Twin

DXCenter

A Unity authoring environment for LG Energy Solution content with nine EditorWindow tools, mapping rules, and a cleaner runtime path for non-developer operators.

  • Problem: Production content needed repeatable authoring, validation, and handoff without depending on developer-only editing paths.
  • Build: EditorWindow tools, state management, undo, data mapping, preview/runtime separation, and operator-facing authoring flow.
  • Outcome: Lower repeated setup cost; content production becomes a maintainable workflow.
These projects cover robot control, BIM section tools, EditorWindow tooling, and manufacturing ERP installed, checked, and handed over to operators.

BIM Runtime Tooling

WatchBIM

A Unity BIM runtime with a custom hit engine, station-based cross-section generation, a 2D analysis viewer, and camera controls for inspecting large models.

  • Problem: Large BIM scenes needed accurate selection, reliable movement, and in-runtime cross-section analysis.
  • Build: Triangle caching, hit filtering, geometry jobs, plane intersection, segment grouping, 3D-to-2D conversion, and slope labeling.
  • Outcome: The viewer includes runtime section cutting, hit testing, linked 2D analysis, and slope labeling.
