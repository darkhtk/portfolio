AI Systems · 1/2

Agent workflow kernel · self-host developer tool

Agent Workflow Kernel

Ops-Cure Kernel

A channel-native state/event kernel. Space / Actor / Event / Behavior — four pieces of vocabulary that the kernel commits to, with three behaviors running on top.

  • Problem: Agent workflows, remote execution, and dialogue rooms tend to fork. Can the kernel itself stay agnostic about the domain?
  • Build: Channel-native state/event core on FastAPI + SQLite. Discord transport, behavior plugin registry, canonical DB, three behaviors (orchestration / remote_codex / chat), three runtimes (pc_launcher · remote_executor · chat_participant).
  • Outcome: Three fundamentally different behaviors operating on the same Space/Actor/Event substrate — direct proof the abstraction is real.
Self-host Developer Tool

DeskRelay

A self-host developer tool that remotes Claude Code sessions running on your own PC to a browser or mobile. A single server PC runs site-frontend, site-backend, and a connector daemon. Other PCs in the same LAN or Tailscale register as devices.

  • Problem: Local agent tools are powerful because they sit beside the user's repos, shell, and tokens — but that also pins work to one keyboard.
  • Build: Solid + Vite SPA (:18193), Hono + Bun backend (:18192), pc-connector-daemon (:18191 / :18091), behavior-remote-claude, Capacitor Android app, registration automation + validation report.
  • Outcome: Public v0.0.0 self-host tool at github.com/darkhtk/deskrelay. Finished in an operable form that plugs into a daily workflow.

AI Systems · 2/2

Local LLM R&D · AI × XR in operation

Local LLM R&D

GenWorld + Ollama

Ported a Phaser 3 TS-based RPG to Unity 2D C# while designing a local Ollama LLM-backed NPC cognition / dialogue system. An R&D case validating offline-first and graceful fallback as operational requirements.

  • Problem: The game has to keep running even when the LLM cuts out. Not a demo — an operational experiment.
  • Build: NPC cognition context + mood state + skills layer. LLM responses combined with a pre-defined dialogue graph for graceful fallback. Offline mode supported.
  • Outcome: Rich dialogue while the LLM is up; a mode close to a classic RPG dialogue system when it's down. Same NPC and same scenario doesn't break in either mode.
XR × Generative AI · Operations

Neostalgia

Visitor interview → asset generation → XR sequencing → operations dashboard. A live exhibition where AI survived public operation. Evidence that AI doesn't just run — it needs an operations surface.

  • Problem: Voice input, AI generation, XR sequencing, and operator flow all had to stay coherent under live visitor traffic.
  • Build: Whisper · GPT · TTS · Skybox AI · Meshy · GCP storage · XR timing · session logging · operations dashboard.
  • Outcome: BIFAN XR Official Selection, MSIT Minister Citation, 130+ direct participants. A public AI XR system that held up in operation.

Industrial Software · 1/2

Robotics control · operator tooling

Industrial XR × Robotics

VR Robot Teleoperation

A full Quest 3 to Doosan A0912 control path through Unity, Flask, RoboDK, calibration, safety logic, and later in-house Jacobian IK ownership.

  • Problem: XR input had to control an industrial robot with stable mapping, safe movement, and operator-readable constraints.
  • Build: Controller filtering, coordinate transforms, bridge APIs, safety boxes, deadman logic, resend control, and IK continuation.
  • Outcome: Public demo at BEXCO. Proof that the AI-centered portfolio still rests on real control, safety, and runtime discipline.
Simulation Tooling · Digital Twin

DXCenter

A Unity authoring environment for LG Energy Solution content with nine EditorWindow tools, mapping rules, and a cleaner runtime path for non-developer operators.

  • Problem: Production content needed repeatable authoring, validation, and handoff without depending on developer-only editing paths.
  • Build: EditorWindow tools, state management, undo, data mapping, preview/runtime separation, and operator-facing authoring flow.
  • Outcome: Lower repeated setup cost; content production becomes a maintainable workflow.
Industrial software is not the headline direction — it is the execution base: control, tools, operators, geometry, business workflow, and delivery habits that make the AI systems credible.

Industrial Software · 2/2

BIM geometry · ERP workflow · field delivery habits

Separate from the AI cases, the industrial track was finished with the same discipline — heavy geometry, simulator delivery, manufacturing workflow design, hardware setup, and operator-facing runtime work.

BIM Runtime Tooling

WatchBIM

A Unity BIM runtime built around a custom hit engine, station-based cross-section generation, 2D analysis viewer, and a tool-grade camera system for heavy geometry inspection.

  • Problem: Large BIM scenes needed accurate selection, reliable movement, and in-runtime cross-section analysis.
  • Build: Triangle caching, hit filtering, geometry jobs, plane intersection, segment grouping, 3D-to-2D conversion, and slope labeling.
  • Outcome: A practical viewer and analysis tool that goes beyond visualization into geometry and domain logic ownership.
