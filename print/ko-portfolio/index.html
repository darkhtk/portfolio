AI Systems · 1/2

에이전트 커널 · self-host 개발자 도구

Agent Workflow Kernel

Ops-Cure 커널

채널 단위 state/event 커널. Space / Actor / Event / Behavior 의 4가지 어휘로 커널을 범용화하고, 그 위에 세 가지 behavior 를 같은 추상화로 운영했습니다.

  • Problem: 에이전트 워크플로 · 원격 실행 · 대화방 — 서로 다른 도메인이 매번 fork 되는 문제. 커널 자체가 도메인을 모르게 만들 수 있는가.
  • Build: FastAPI + SQLite 위의 채널 단위 state/event 코어, Discord transport, behavior 플러그인 레지스트리, canonical DB, orchestration / remote_codex / chat 세 behavior, pc_launcher · remote_executor · chat_participant 런타임.
  • Outcome: 세 behavior 가 같은 Space/Actor/Event 위에 운영된다는 사실 — 추상화가 실체라는 직접적 증거.
Self-host Developer Tool

DeskRelay

내 PC 에서 실행되는 Claude Code 세션을 브라우저·모바일에서 안전하게 원격 조작하는 self-host 개발자 도구. 서버 PC 한 대가 site-frontend, site-backend, connector daemon 을 띄우고 LAN/Tailscale 안의 다른 PC 를 디바이스로 등록합니다.

  • Problem: 로컬 에이전트 도구는 사용자 PC 의 repo · shell · token 옆에 있어 강력하지만, 그래서 한 자리에 묶인다는 한계.
  • Build: Solid + Vite SPA (:18193), Hono + Bun backend (:18192), pc-connector-daemon (:18191 / :18091), behavior-remote-claude, Capacitor Android 앱, 등록 자동화 + 검증 리포트.
  • Outcome: 공개 v0.0.0 self-host 도구. github.com/darkhtk/deskrelay. 일상 워크플로우에 끼워 쓰는 형태로 마무리.

로컬 LLM R&D · AI × XR 운영 사례

Local LLM R&D

GenWorld + Ollama

Phaser 3 TS 기반 RPG 를 Unity 2D C# 로 포팅하면서, 로컬 Ollama LLM 기반 NPC 인지·대화 시스템을 설계했습니다. 오프라인 우선과 graceful fallback 을 운영 관점에서 검증한 R&D 사례.

  • Problem: LLM 응답이 끊겨도 게임이 계속 돌아가야 한다. 데모용이 아니라 운영 관점의 실험.
  • Build: NPC 인지 컨텍스트 + mood state + skills 레이어. LLM 응답 결합 + 사전 정의 대사 그래프로 graceful fallback. 오프라인 모드 지원.
  • Outcome: LLM 켜진 동안은 풍부한 대화, 꺼지면 RPG 대화 시스템에 가까운 모드. 같은 NPC · 같은 시나리오에서 양 모드 모두 흐름이 깨지지 않음을 검증.
XR × 생성형 AI · 운영

Neostalgia

방문자 인터뷰 → 자산 생성 → XR 시퀀싱 → 운영 대시보드까지, AI 가 실제 전시 운영에서 살아남게 만든 사례. AI 가 작동만 하는 것이 아니라 운영 표면을 가져야 한다는 증거.

  • Problem: 음성 입력 · AI 생성 · XR 시퀀싱 · 운영자 흐름이 live 방문자 트래픽 안에서 일관되게 동작해야 함.
  • Build: Whisper · GPT · TTS · Skybox AI · Meshy · GCP storage · XR timing · 세션 로깅 · 운영 대시보드.
  • Outcome: BIFAN XR 선정, MSIT 장관 표창, 130+ 직접 참여자. 공개 운영에서 견딘 AI XR 시스템.

Industrial XR × Robotics

VR 로봇 원격 조작

Quest 3 입력에서 Doosan A0912 산업용 로봇 제어까지의 전체 경로 — Unity 런타임, Flask 브리지, RoboDK, 캘리브레이션, 안전 로직, 그리고 사내 Jacobian IK 확장 — 을 직접 책임진 작업.

  • Problem: XR 입력으로 산업 로봇을 안정적 매핑 · 안전 이동 · 운영자가 읽을 수 있는 제약 조건으로 제어해야 함.
  • Build: 컨트롤러 필터링 · 좌표 변환 · 브리지 API · 안전 박스 · deadman · resend 제어 · IK 확장.
  • Outcome: 부산 BEXCO 엑스포 실시연 + 공개 데모. AI 중심 portfolio 가 실제 제어 · 안전 · 런타임 규율 위에 서 있음을 증명.
Simulation Tooling · Digital Twin

DXCenter

LG Energy Solution 콘텐츠를 위한 Unity 작성 환경. 9개의 EditorWindow 툴 · 데이터 매핑 규칙 · 비개발자 운영자가 쓸 수 있는 런타임 경로를 자체 설계했습니다.

  • Problem: 제작 콘텐츠가 반복 가능한 작성 · 검증 · 핸드오프를 거쳐야 함. 개발자만 편집 가능한 경로에 의존하면 안 됨.
  • Build: EditorWindow 툴 모음, 상태 관리, undo, 데이터 매핑, preview/runtime 분리, 운영자용 작성 흐름.
  • Outcome: 반복 셋업 비용 절감, 콘텐츠 제작이 유지 가능한 워크플로우로 정착.
산업 Unity 트랙은 AI 헤드라인이 아닙니다. 그러나 제어 · 툴 · 운영자 · 지오메트리 · 납품 습관 — AI 시스템을 신뢰할 수 있게 만드는 베이스입니다.
