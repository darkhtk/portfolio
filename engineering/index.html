관련 케이스 · VR Robot ↗
// demo — 실제 시연 영상
// problem

목표 자세(TCP)를 주면 각 관절 각도를 역으로 풀어야 하는데, 해는 여럿이거나 없을 수 있습니다. 특히 팔이 일직선으로 펴지는 특이점(singularity) 근처에서는 순수 역행렬 방식이 관절 속도를 폭주시켜 로봇이 튑니다. 외부 솔버(RoboDK)에 매 프레임 의존하면 실시간성·이식성도 떨어졌습니다.

// approach

자코비안 전치(transpose)가 아니라 감쇠 최소자승(Damped Least Squares) 으로 풀었습니다. 특이점에 가까워질수록 감쇠를 키워, 정확도를 약간 희생하는 대신 해가 발산하지 않게 만듭니다. VR 입력은 이 솔버의 목표 자세로 직접 매핑되고, 잘못된 명령은 로봇으로 흐르기 전에 1차 필터링됩니다.

런타임 단면 생성 엔진.

Computational Geometry Mesh Slicing Custom Hit Engine 2D Viewer

외부 BIM 도구가 못 다루는 운영 요구 — 런타임에서 임의 평면으로 단면을 만들고, 그 결과를 2D 뷰어에서 측정·분석하는 기능을 직접 구현했습니다. 대용량 모델에서의 픽킹·hover 도 표준 Raycast 대신 커스텀 히트 엔진으로 처리했습니다.

관련 케이스 · WatchBIM ↗
// demo — 실제 시연 영상
// problem

운영자는 "이 위치를 잘라서 단면을 보고 치수를 재고 싶다" 고 요구하지만, 일반 BIM 뷰어는 런타임 단면 생성·실시간 2D 분석을 제공하지 않습니다. 게다가 대용량 모델에서는 표준 Physics.Raycast 만으로 안정적인 선택이 어려웠습니다.

// approach

외부 BIM 도구가 막힌 부분이라 필요한 기하 연산을 직접 짰습니다. 2D 분석의 선분 교차 판정은 외적 부호(orientation) 기반으로 구현했고, 메시 절단·클리핑은 컴퓨테이셔널 지오메트리 라이브러리(Habrador — cut-mesh-with-plane · 폴리곤 클리핑 · ear-clipping 삼각분할) 위에 올렸습니다. 대용량 정점 처리는 Unity Job System·Burst 로 병렬화했고, 3D 모델과 2D 뷰어는 같은 데이터 모델로 연동됩니다.

// live — 캔버스를 드래그하세요 · 단면 개념 시각화
// code — 실제 구현 기반 (WBExtensions)
// 2D 선분 교차 판정 — 외적 부호(orientation) 기반
int Orient(Pt p, Pt q, Pt r) {
    float v = (q.Y - p.Y) * (r.X - q.X) - (q.X - p.X) * (r.Y - q.Y);
    return v == 0 ? 0 : (v > 0 ? 1 : 2);     // 공선 / CW / CCW
}
bool IsIntersect(Pt p1, Pt q1, Pt p2, Pt q2) {
    int o1 = Orient(p1,q1,p2), o2 = Orient(p1,q1,q2);
    int o3 = Orient(p2,q2,p1), o4 = Orient(p2,q2,q1);
    return o1 != o2 && o3 != o4;              // (+ 공선 특수케이스)
}
// 메시 절단·삼각분할: Habrador (cut-mesh-with-plane, ear-clipping)
// 대용량 정점 처리: Unity Job System + Burst

비개발자를 위한 도구 묶음.

Editor Scripting 9 EditorWindows Data Mapping Digital Twin

가장 어려운 건 알고리즘이 아니라, 콘텐츠 제작자·운영자가 코드를 만지지 않고도 제품을 운영하게 만드는 것이었습니다. 데이터 매핑·자산 등록·디지털 트윈 모니터링·검증을 9개의 EditorWindow 로 묶어 반복 비용을 도구로 흡수했습니다.

관련 케이스 · DX Center ↗
// problem

전시·디지털 트윈 운영에서 같은 수작업(데이터 매핑, 자산 등록, 라인업 교체)이 반복됐고, 매번 개발자가 붙어야 했습니다. 운영자가 직접 못 하면 도구가 아니라 병목이 됩니다.

// approach

Unity 에디터 확장으로 워크플로 전체를 GUI 화했습니다. EditorWindow · SerializedObject · 커스텀 인스펙터로 외부 데이터를 씬 오브젝트에 매핑하고, 적용 전 검증과 Undo 등록까지 도구 안에서 처리합니다. 비개발자가 안전하게 반복 작업을 끝낼 수 있는 형태.

// viz — 외부 데이터 → 씬 오브젝트 매핑·검증 흐름
// code — 개념 코드 (핵심 패턴)
// 비개발자용 EditorWindow 의 핵심 패턴
public class DataMapperWindow : EditorWindow {
    [MenuItem("DXCenter/Data Mapper")]
    static void Open() => GetWindow<DataMapperWindow>("Data Mapper");

    void OnGUI() {
        foreach (var row in mapping)                 // 외부 데이터 → 씬 오브젝트
            row.target = (GameObject)EditorGUILayout.ObjectField(
                row.key, row.target, typeof(GameObject), true);

        if (GUILayout.Button("검증 후 적용") && Validate(mapping)) {
            Undo.RecordObjects(Targets(mapping), "Apply Mapping");
            Apply(mapping);                          // 직렬화 · 저장
        }
    }
}
