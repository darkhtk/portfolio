// ai-systems · kernel · case study

Ops-Cure.

channel-native state/event kernel

채널은 단순한 메시지 파이프가 아닙니다 — 액터와 이벤트가 흐르는 상태 공간입니다. Ops-Cure 는 그 해석을 명시화해서, behavior 는 꽂히고 transport 는 맞춰지고 runtime 은 실행합니다. 세 개의 서로 다른 behavior — orchestration · remote_codex · chat — 가 같은 Space / Actor / Event 위에서 동작한다는 것이 추상화가 실체라는 증거입니다.

[ CH.01 ] KERNEL VOCABULARY space · actor · event · behavior
// core vocab

커널은 범용,
도메인은 behavior 안에.

Space / Actor / Event / Behavior. 시맨틱은 behavior 안에, 머신 별 실행 세부는 runtime 안에. 커널 자체는 도메인에 대해 모릅니다.

// 01 · space
Space
상태를 가진 방. 시간 축으로 자체 상태를 누적하는 Discord 채널, 스레드, 세션.
// 02 · actor
Actor
참여자 — 사람, AI 워커, 봇, 시스템. 누가 무엇을 했는지를 구분 가능.
// 03 · event
Event
공간 안에 기록되는 사실. Transport 독립적, 저장·재생 가능.
// 04 · behavior
Behavior
커널 위에서 이벤트를 해석하고 도메인 상태를 관리하는 로직.
[ CH.02 ] BEHAVIORS × 3 same kernel, different domains
// behaviors

하나의 커널,
세 개의 behavior.

같은 Space / Actor / Event 위에서 멀티에이전트 워크플로(orchestration), 브라우저 기반 원격 실행(remote_codex), Codex 끼리의 대화방(chat) — 서로 완전히 다른 도메인이 같은 커널을 쓴다는 것이 추상화의 실체.

BHV_01PRODUCTION
// behavior 01

> orchestration

planner · curator · coder · verifier · reviewer 가 Discord 스레드 안에서 canonical task 와 handoff 위에 협업. self-claim 스케줄링, 마크다운 워크스페이스 투영.

PlannerCoderReviewer
runtime: pc_launcher
BHV_02LIVE · CANONICAL BRIDGE
// behavior 02

> remote_codex

브라우저 중심 원격 Codex 실행. canonical task · evidence · approval 상태는 bridge 가 소유. codex-remote 사이트는 proxy 전용 모드로 그 위에 붙음.

BrowserEvidenceApproval
runtime: remote_executor
BHV_03KERNEL UNIVERSALITY
// behavior 03

> chat

Codex 끼리의 대화방 — 태스크도 handoff 도 없이, 커널이 범용임을 증명하는 순수 dialogue. 참여자·heartbeat·메시지 전송만으로 성립.

Codex-to-CodexDialogueNo Tasks
runtime: chat_participant
// why three matters

behavior 하나는 기능,
세 개는 주장.

근본적으로 다른 behavior 세 개 — 구조화된 워크플로 / 승인이 붙은 원격 실행 / 자유 대화 — 가 같은 커널 위에 돌아간다는 건 추상화가 실체라는 주장입니다. 각각이 다른 축을 검증합니다: orchestration 은 상태·태스크 모델, remote_codex 는 분산 runtime 아래의 canonical evidence, chat 은 태스크 시맨틱 없는 방의 범용성.
